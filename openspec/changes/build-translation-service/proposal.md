## 为什么

TransFlow 需要一个面向生产环境的翻译服务，将混合源语言的字幕片段数组转换为多个目标语言的有序译文。服务必须在大请求和并发负载下保持响应结构稳定，并通过可配置、可观测的 FastAPI 部署运行本地 Hy-MT2-1.8B 模型。

## 变更内容

- 新增同步 `POST /translate` API，最多接受 120 条文本和可配置数量的目标语言。
- 为每个目标语言保留全部输入位置；精确空字符串 `""` 原样返回且不调用模型。
- 每条非空文本独立翻译，允许一个请求包含不同源语言，并通过索引重组保证输出数量，不依赖模型生成的分隔符。
- 校验 Hy-MT2 语言代码，阿拉伯语使用 `ar`，拒绝不支持或重复的目标语言。
- 新增有界且可配置的调度器，负责大请求切分、背压、64 个并发 API 请求，并将连续批处理交给 vLLM。
- 通过内部兼容 OpenAI API 的 vLLM 服务接入 Hy-MT2-1.8B，使用已验证的 `vllm/vllm-openai:v0.28.0` 镜像。
- 新增基于 TOML 的配置、简要参数注释和用于部署覆盖的环境变量。
- 新增 FastAPI 与 vLLM 的容器部署文件；项目内模型只读挂载，不写入 Git 或容器镜像。
- 新增存活、就绪、指标、模型冒烟、集成和渐进式并发负载测试，以实测结果确定 GPU 调度参数。

## 能力范围

### 新增能力

- `translation-api`：定义 `POST /translate` 的请求校验、多语言翻译、稳定有序响应、空输入处理和公开错误行为。
- `translation-runtime`：定义配置、有界调度、vLLM 集成、生命周期、可观测性端点、模型存储、容器部署和容量验证。

### 修改能力

无。

## 影响

- 引入新的 Python 3.12 FastAPI 应用及其测试套件。
- 新增 FastAPI、类型化配置、异步 HTTP、数据校验、日志和指标等运行时依赖。
- 新增 `config.toml`、项目打包元数据、模型目录排除规则、Docker 构建与 Compose 文件以及压测工具。
- 运行时依赖本地 Hy-MT2-1.8B 文件和支持 GPU 的 vLLM 容器。
- 公开 `POST /translate`，同时默认仅允许部署内部网络访问兼容 OpenAI API 的 vLLM 服务。
