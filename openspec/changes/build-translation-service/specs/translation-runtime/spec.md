## 用途

定义翻译服务及其本地 Hz-MT2 推理后端在配置、部署、调度、观测和容量测试方面的运行契约。

## ADDED Requirements

### Requirement: TOML 运行配置
服务 MUST（必须）从项目级 `config.toml` 加载运行配置，在接受流量前完成校验，并支持通过环境变量覆盖部署参数。配置必须覆盖 API 限制、调度器、推理端点、生成控制、超时、公开响应元数据、日志和指标；不直观的参数与单位必须带有简短注释。

#### Scenario: 有效配置启动服务
- **WHEN** `config.toml` 包含有效配置，且所有必需的部署覆盖值都能解析
- **THEN** 服务使用校验后的有效配置启动

#### Scenario: 环境变量覆盖部署参数
- **WHEN** 允许的环境变量覆盖推理基础 URL
- **THEN** 有效配置使用环境变量值，且不修改 `config.toml`

#### Scenario: 配置了无效安全限制
- **WHEN** 必需限制缺失、格式错误或超出允许范围
- **THEN** 服务启动失败，并在错误中指出无效配置项

### Requirement: 有界请求调度
运行时 MUST（必须）允许不超过配置数量的并发 API 请求，默认值为 64，并限制排队和在途推理任务。请求必须按可配置的调度分片大小切分，默认每片 60 个文本位置，同时保留用于重组原子响应的请求与索引元数据。

#### Scenario: 120 条请求使用默认调度分片
- **WHEN** 请求包含 120 条文本，调度分片大小为 60
- **THEN** 调度器将其作为两个有界文本位置分片处理，且不改变公开响应结构

#### Scenario: 并发请求竞争推理容量
- **WHEN** 多个已准入请求存在待处理翻译任务
- **THEN** 调度器不允许任何请求绕过全局在途限制，并保证各已准入请求持续推进

#### Scenario: 调用方断开连接
- **WHEN** 调用方在翻译完成前断开连接
- **THEN** 运行时取消该请求的排队任务，并尝试中止其活动后端生成任务

### Requirement: 独立翻译单元
运行时 MUST（必须）将每个精确非空的 `(请求, 文本索引, 目标语言)` 组合提交为独立跟踪的生成单元，并依靠后端连续批处理提高 GPU 效率。运行时不得依赖模型复现生成分隔符或指定条目数量来恢复结果边界。

#### Scenario: 模型输出包含类似分隔符的文本
- **WHEN** 生成译文包含标点或类似分隔符的文本
- **THEN** 该内容仍只属于其独立翻译单元，且不改变响应结果数量

#### Scenario: 调度到空原文
- **WHEN** 调度器遇到精确空字符串原文
- **THEN** 运行时在本地完成该位置，不向后端发送生成请求

### Requirement: Hz-MT2 推理后端
部署 MUST（必须）通过内部兼容 OpenAI API 的聊天补全端点使用本地 Hz-MT2 模型。对于每个生成单元，运行时必须在提示词中写入目标语言全名，只请求翻译结果，应用明确配置的生成参数，并执行后端和请求期限。

#### Scenario: 后端完成翻译
- **WHEN** 内部后端返回成功的聊天补全响应
- **THEN** 助手内容作为对应请求、文本索引和目标语言的译文

#### Scenario: 后端不可用
- **WHEN** 内部推理健康检查失败
- **THEN** 就绪状态为失败，新翻译请求收到 HTTP 503

#### Scenario: 模型生成默认值与服务配置不同
- **WHEN** 模型镜像提供自己的采样默认值
- **THEN** 每个翻译请求均使用服务有效配置中明确指定的生成参数

### Requirement: 服务生命周期与健康状态
运行时 MUST（必须）提供存活和就绪端点。存活状态表示 API 进程正在运行；在配置有效且推理后端可访问前，就绪检查必须保持失败。关闭时必须停止准入，按配置宽限期取消或排空任务，并关闭后端客户端。

#### Scenario: 模型冷启动
- **WHEN** API 已运行，但模型后端仍在加载或编译
- **THEN** 存活检查成功，就绪检查保持失败

#### Scenario: 后端变为就绪
- **WHEN** 配置的推理后端通过健康检查
- **THEN** 就绪检查成功，翻译请求可以被准入

### Requirement: 可观测且重视隐私的运行方式
服务 MUST（必须）提供机器可读指标和结构化日志，覆盖请求数、状态码、队列深度、活动推理单元、排队时间、后端延迟、总处理时间、超时、取消和失败。日志和指标必须通过请求标识关联任务，且默认不得包含完整原文或译文。

#### Scenario: 观测成功请求
- **WHEN** 翻译请求完成
- **THEN** 指标和日志记录请求维度、耗时、结果及请求标识，但不记录完整文本内容

#### Scenario: 出现队列压力
- **WHEN** 待处理或活动任务接近配置容量
- **THEN** 暴露的指标显示诊断压力所需的队列和在途使用情况

### Requirement: 可复现的容器部署
项目 MUST（必须）提供 FastAPI 应用的 Docker 构建文件，以及将 API 与 `vllm/vllm-openai:v0.28.0` 作为独立推理服务运行的 Docker Compose 部署。默认部署必须公开 FastAPI 端口、将 vLLM API 保持在部署私有网络、只读挂载 `model/Hz-MT2`，并提供具备足够冷启动宽限期的健康检查。

#### Scenario: Compose 使用本地模型文件启动
- **WHEN** 模型文件位于文档指定的项目本地模型目录，运维人员启动 Compose
- **THEN** vLLM 从只读挂载加载模型，并在 vLLM 健康后使 FastAPI 进入就绪状态

#### Scenario: 检查模型产物打包
- **WHEN** 检查 Git 状态或 API 的 Docker 构建上下文
- **THEN** 模型权重文件不进入源代码管理，也不进入 API 镜像构建上下文

#### Scenario: 检查内部推理端点
- **WHEN** 未使用调试覆盖启动默认 Compose 部署
- **THEN** API 服务可以访问 vLLM 端口，但该端口不会发布到外部主机接口

### Requirement: 基于实测的容量配置
项目 MUST（必须）提供可重复的模型冒烟测试和负载测试，覆盖调度分片大小 `8`、`16`、`32`、`60`，API 并发量 `1`、`8`、`16`、`32`、`64`，以及文档记录的文本长度和目标语言组合。测试报告必须记录吞吐量、排队时间、延迟分位数、GPU 峰值显存、超时与错误数、输出结构错误和 OOM 事件。生产 GPU 调度值必须取自成功的测试报告，不得在启动时通过不断探测直到 OOM 自动确定。

#### Scenario: 64 请求并发验收
- **WHEN** 文档规定的 64 并发请求配置在默认部署上运行
- **THEN** 服务准入 64 个有效请求，在压测配置的期限内完成，保持所有输出结构正确，且不发生进程崩溃或 GPU OOM

#### Scenario: 候选调优值失败
- **WHEN** 某项压测配置导致 OOM、超时、服务崩溃或输出结构错误
- **THEN** 该配置被报告为失败，且不会被选为生产默认值
