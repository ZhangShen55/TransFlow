# 6,400 请求持续负载测试报告

## 测试结论

在当前单 GPU 生产配置下，TransFlow 完成了 64 并发、6,400 次请求的持续负载测试。每个请求包含 60 条非空混合源语言文本，并翻译为 6 个目标语言，共执行 2,304,000 个独立模型翻译单元。

压测客户端观测到 6,400/6,400 个 HTTP 200，成功率 100%。没有发生客户端错误、超时、取消、OOM 或输出数量/顺序错误；测试结束后 API 与 vLLM 均保持健康，容器没有重启。

本次固定语料持续稳定性测试通过。

## 同期 429 说明

测试前 Prometheus 基线为 7 个 HTTP 200、6 个 HTTP 422，没有 HTTP 429。测试后为 6,407 个 HTTP 200、6 个 HTTP 422、1 个 HTTP 429。

HTTP 200 的增量正好是 6,400，且客户端报告的 6,400 次请求全部为 HTTP 200，因此同期的 1 个 HTTP 429 不属于压测客户端请求。它来自压测之外到达服务的额外请求；当压测已经占满 64 个准入槽位时，额外请求按设计返回 429。

这说明服务能够稳定承载本次 64 并发，但在准入上限设为 64 时不会再为额外流量预留容量。正式压测应隔离其他调用方；生产环境如需保证 64 个业务请求之外仍可接受额外请求，需要提高准入上限并重新验证资源与延迟。

## 适用边界

- 本次是固定短字幕语料测试，vLLM 已启用前缀缓存。结果适合评估重复固定语料下的持续稳定性，不应直接视为完全随机生产文本的保守吞吐下限。
- 本次只校验 HTTP 状态、目标语言顺序和输出数组数量，不评价每条译文的语义质量。
- 所有文本均为非空，因此结果不包含空字符串本地短路带来的吞吐提升。
- 文本长度远低于 4,096 字符和 256 输出 token 上限；长文本场景需要单独测试。
- 更换 GPU、vLLM 镜像、模型文件、生成参数、在途序列或微批配置后，本报告不再代表新配置。

机器可读结果见 `docs/reports/load-6400-c64-text60-lang6.json`。本机原始报告保留在已忽略的 `reports/load-6400-c64-text60-lang6.json`。
